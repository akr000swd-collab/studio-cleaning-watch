# スタジオ清掃監視ダッシュボード (studio-cleaning-watch)

Googleカレンダーの「予約」と「清掃予定」を突き合わせて、**清掃が入らないまま次の予約が始まりそうなスタジオ**を検知し、ブラウザ画面上で警報(音+バナー)を出し続けるWebアプリです。

- チームメンバーはブラウザでURLを開いておくだけで使えます(Claudeのインストール不要、アプリのインストール不要)。
- Next.js + Vercelで動作し、追加のサーバー費用はかかりません(Vercel無料枠の範囲で想定)。
- Googleカレンダーへのアクセスは、Googleのサービスアカウントを使って読み取ります(各カレンダーをサービスアカウントに共有するだけでOK)。

## 検知ロジックの考え方

1. 各スタジオの「予約カレンダー」から予約(利用)予定を取得します。
2. 連続する2つの予約の間の「隙間」(前の利用終了〜次の利用開始)を見つけます。
3. 清掃担当者(A・B・Cさんなど)のカレンダーの中から、**タイトルにそのスタジオ名を含む予定**を探し、その隙間の中で終わる清掃予定があるかを確認します。
4. 清掃予定が見つからない隙間があれば:
   - 次の予約の開始時刻を**すでに過ぎている** → 「清掃なしで使用中」(赤・警報)
   - 次の予約の開始まで **設定したしきい値(既定60分)を切っている** → 「まもなく開始」(赤・警報、音が鳴る)
   - それより先 → 「清掃未予定」(黄色・音は鳴らさない注意表示)
5. 上記に該当しなければ「問題なし」(緑)。

ダッシュボードは常に**その時点の最新のGoogleカレンダーの状態**を直接取得して判定するので、急な予約追加もすぐ反映されます(裏側でスケジュール実行するような仕組みは不要です)。

## 事前に必要なもの

- Googleアカウント(スタジオのカレンダーを管理しているもの)
- Google Cloud Platform (GCP) のプロジェクト
- GitHubアカウント
- Vercelアカウント
- Node.js 18以上(ローカルで動作確認したい場合のみ)

---

## セットアップ手順

### 1. GCPでサービスアカウントを作る

1. [Google Cloud Console](https://console.cloud.google.com/) で対象のプロジェクトを開く(なければ新規作成)。
2. 「APIとサービス」→「ライブラリ」から **Google Calendar API** を有効化する。
3. 「APIとサービス」→「認証情報」→「認証情報を作成」→「サービスアカウント」を選び、名前を付けて作成する(ロールの付与は不要でOK)。
4. 作成したサービスアカウントの「鍵」タブから「鍵を追加」→「新しい鍵を作成」→ JSON を選んでダウンロードする。
5. ダウンロードしたJSONの中の `client_email` と `private_key` を控えておく(後で環境変数に設定します)。

### 2. Googleカレンダーをサービスアカウントに共有する

対象になるすべてのカレンダー(各スタジオの予約カレンダー、清掃担当のA・B・Cさんそれぞれのカレンダー)について、以下を行います。

1. Googleカレンダーの該当カレンダーの「設定」を開く。
2. 「特定のユーザーとの共有」で、手順1の `client_email`(例: `xxx@your-project.iam.gserviceaccount.com`)を追加し、権限は「**予定の詳細をすべて表示**」にする。
3. 同じ設定画面の「カレンダーの統合」にある「**カレンダーID**」をメモしておく(例: `abcdef123@group.calendar.google.com` や、個人アカウントならそのメールアドレス)。

これを、監視したい全スタジオの予約カレンダー分 + 清掃担当者(A・B・Cさん)のカレンダー分、繰り返します。

### 3. ローカルの設定ファイルを準備する

`.env.example` を `.env.local` にコピーして、値を埋めます。

```bash
cp .env.example .env.local
```

`STUDIOS_CONFIG` は、スタジオ名(清掃予定のタイトルに含まれる文字列と一致させること)とそのカレンダーIDの配列です。

```json
[
  { "name": "Aスタジオ", "reservationCalendarId": "studio-a@group.calendar.google.com" },
  { "name": "Bスタジオ", "reservationCalendarId": "studio-b@group.calendar.google.com" }
]
```

`CLEANING_CALENDARS_CONFIG` は、清掃担当者名(表示用)とそのカレンダーIDの配列です。

```json
[
  { "staff": "Aさん", "calendarId": "staff-a@example.com" },
  { "staff": "Bさん", "calendarId": "staff-b@example.com" }
]
```

`ALERT_THRESHOLD_MINUTES` は既定で `60`(残り60分を切ったら警報)にしてあります。ヒアリング時のご希望通りの設定です。変更したい場合はここを書き換えてください。

`APP_PASSWORD` を設定すると、ダッシュボードを開く前にパスワード入力が必要になります(社外に漏れると誰でもカレンダー状況が見えてしまうため、設定を推奨します)。未設定なら誰でもアクセスできます。

### 4. ローカルで動作確認(任意)

```bash
npm install
npm run dev
```

`http://localhost:3000` を開いて、スタジオごとのカードが表示されること、意図的に「清掃予定のない隙間」を作ったテスト予約を入れてみて警報(赤バナー・音)が出ることを確認してください。初回は右上の「🔊 音を有効にする」ボタンを押す必要があります(ブラウザの自動再生制限のため)。

### 5. GitHubに登録する

このフォルダはすでに `git init` 済みです。GitHub上に空のリポジトリを作り、push してください。

```bash
git remote add origin https://github.com/<あなたのアカウント>/studio-cleaning-watch.git
git branch -M main
git push -u origin main
```

(`gh` コマンドが使える場合は `gh repo create studio-cleaning-watch --private --source=. --push` でも作成できます)

### 6. Vercelにデプロイする

1. [Vercel](https://vercel.com/) のダッシュボードで「Add New...」→「Project」→ 先ほどのGitHubリポジトリを選択してImport。
2. 「Environment Variables」に、`.env.local` に書いたものと同じ内容をすべて登録する(`GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` は改行を含みますが、Vercelの入力欄にそのまま貼り付ければOKです)。
3. 「Deploy」を押す。数分でURLが発行されます。

デプロイ後、環境変数を変更した場合は Vercel 側で再デプロイ(Redeploy)してください。

### 7. チームメンバーへの展開

1. 発行されたURL(`https://studio-cleaning-watch-xxxx.vercel.app` のようなもの)をチームメンバーに共有します。
2. 各メンバーは、フロントデスクのPCやスマホのブラウザでそのURLを開き、`APP_PASSWORD` を設定していればパスワードを入力します。
3. 画面右上の「🔊 音を有効にする」ボタンを一度クリックします(ブラウザごと・端末ごとに1回必要です)。
4. そのままタブを開いたままにしておけば、自動で状況を監視し続けます。

## 運用上の注意

- 警報音を鳴らすには、対象の端末でブラウザのタブが開かれている必要があります(タブを閉じている間は鳴りません)。フロントデスクなど、常時開いておける画面での運用を想定しています。
- 現時点ではダッシュボード表示のみで、メールなどのバックアップ通知は組み込んでいません。必要になったら追加できます。
- 判定に使う「清掃予定と紐づけるスタジオ名」は、清掃予定のタイトルに `STUDIOS_CONFIG` の `name` の文字列が**含まれているか**で判定しています。表記ゆれ(全角/半角など)があると検知漏れの原因になるので、清掃予定を入力する際はスタジオ名の書き方を統一してください。
- `COVERAGE_BUFFER_MINUTES`(既定15分)は、清掃予定が前の利用終了より多少早めに登録されていても正常とみなすための余裕分です。
- `WINDOW_HOURS_BEFORE` / `WINDOW_HOURS_AFTER`(既定48時間)の範囲でカレンダーを確認します。

## 設定を後から変更したいとき

Vercelの「Settings」→「Environment Variables」で値を編集し、再デプロイすれば反映されます(コードの変更は不要です)。
